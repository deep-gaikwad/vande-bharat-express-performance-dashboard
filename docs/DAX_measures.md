# Vande Bharat Express — DAX Measures

## Overview

This document contains the DAX measures used in the Vande Bharat Express Performance & Passenger Analytics Dashboard. These measures analyze train performance, passenger volume, occupancy, revenue, punctuality, and route-level performance in Power BI.

**Data model:** `Fact_Bookings`, `Train_Master`, `State_Master`

---

## 1. Key Performance Indicators (KPIs)

### Total Trains
```dax
Total Trains =
DISTINCTCOUNT ( Fact_Bookings[Train_No] )
```
Counts the distinct train numbers available in the current filter context.

### Total Passengers
```dax
Total Passengers =
SUM ( Fact_Bookings[Passengers] )
```
Calculates the total number of passengers represented in the booking data.

### Average Occupancy
```dax
Avg Occupancy =
AVERAGE ( Fact_Bookings[Occupancy_%] )
```
Calculates the average occupancy percentage across the filtered records. Format this measure as a percentage if the source column stores decimal values.

### Average Speed
```dax
Avg Speed =
AVERAGE ( Fact_Bookings[Speed_kmph] )
```
Calculates the average recorded train speed in kilometres per hour.

### On-Time Percentage
```dax
On Time % =
DIVIDE (
    CALCULATE (
        SUM ( Fact_Bookings[Passengers] ),
        Fact_Bookings[On_Time] = TRUE ()
    ),
    [Total Passengers]
)
```
Calculates the share of passengers associated with records marked as on time. This is a passenger-weighted punctuality measure, not the percentage of trains arriving on time.

**Format:** Percentage.

### Total Revenue
```dax
Total Revenue =
SUM ( Fact_Bookings[Revenue] )
```
Calculates total revenue across the selected trains, routes, dates, and other active filters.

## 4. Class-Wise Passenger Analysis

### Class Passengers
```dax
Class Passengers =
SUM ( Fact_Bookings[Passengers] )
```
Calculates passenger volume for each class when a class field is used in the visual.

### Percentage of Total Passengers
```dax
% of Total Passengers =
DIVIDE (
    [Total Passengers],
    CALCULATE (
        [Total Passengers],
        ALL ( Fact_Bookings[Class] )
    )
)
```
Calculates each class's share of passengers by removing the filter on `Fact_Bookings[Class]` while retaining other applicable filters.

**Format:** Percentage.

## 7. Performance Leaderboards

The following measures support leaderboard visuals. They use the model's existing route and train fields and should be checked against the exact fields used in the report visuals.

### Highest Revenue Route
Use the route field and `[Route Revenue]` measure to rank routes by revenue.

### Highest Revenue Route Value
```dax
Highest Revenue Route Value =
MAXX (
    ALL ( Fact_Bookings[Route] ),
    CALCULATE ( [Route Revenue] )
)
```
Returns the highest route revenue across routes while retaining other applicable filter context.

### Busiest Train
Use the train number field and `[Train Passengers]` measure to rank trains by passenger volume.

### Best Occupancy Route
Use the route field and `[Route Occupancy]` measure to rank routes by average occupancy.

### Highest Speed Train
Use the train number field and `[Train Avg Speed]` measure to rank trains by average recorded speed.

### Least Average Delay Train
Use the train number field and `[Avg Delay (mins)]` measure to rank trains by average delay, with the lowest value ranked first.

**Note:** These leaderboard descriptions explain the intended ranking logic. If the report uses separate DAX measures to return text labels or `TOPN` results, retain and document the exact formulas from the Power BI model.

## 8. Filter Context and Calculation Notes

- Measures respond to the active report filters and slicers, subject to the filter-removal behaviour of each formula.
- `DIVIDE()` safely handles division by zero or blank denominators.
- `ALL ( Fact_Bookings[Class] )` removes the filter on the specified class column; it does not automatically remove every report filter.
- Passenger-weighted on-time performance should not be described as a train-count-based punctuality rate.
- Average occupancy and speed depend on the values and granularity stored in the source data.
- Confirm that percentage columns use the correct numeric scale before applying percentage formatting.
- Verify leaderboard calculations against the actual model fields and report visuals.

## 9. Data Model

The dashboard uses the following tables:

- `Fact_Bookings` — booking records and performance metrics.
- `Train_Master` — train-related reference information.
- `State_Master` — state-related reference information.

The documented model uses relationships between `Fact_Bookings` and the corresponding master tables. Check the Power BI model view for the actual relationship keys, cardinality, and filter direction.
